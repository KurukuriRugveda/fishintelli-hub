# Aqua Intelligent Hub - Frontend

This is the frontend application for the Aqua Intelligent Hub, built with React and Vite. It provides the user interface for monitoring, data visualization, and interacting with the backend services.

## Technologies Used

- **Framework**: React 19
- **Build Tool**: Vite
- **Styling**: Tailwind CSS
- **Icons**: Lucide React
- **Charts/Data Visualization**: Apache ECharts (`echarts`, `echarts-for-react`)
- **HTTP Client**: Axios
- **Date Formatting**: date-fns
- **Linting**: oxlint

## Getting Started

### Prerequisites

Make sure you have [Node.js](https://nodejs.org/) installed on your machine.

### Installation

1. Open a terminal and navigate to the `frontend` directory:
   ```bash
   cd frontend
   ```

2. Install the required dependencies:
   ```bash
   npm install
   ```

### Development Server

To start the development server, run:

```bash
npm run dev
```

This will start Vite's development server. Open your browser and navigate to the URL provided in the terminal (usually `http://localhost:5173`). The server features Hot Module Replacement (HMR), so the page will automatically reload when you make changes to the code.

### Available Scripts

Here are the scripts you can run via npm:

- `npm run dev`: Starts the development server.
- `npm run build`: Builds the app for production. The output will be placed in the `dist` folder. It bundles React in production mode and optimizes the build for the best performance.
- `npm run lint`: Runs `oxlint` to analyze the code for potential errors or stylistic issues.
- `npm run preview`: Starts a local web server to preview the production build generated by `npm run build`.

## API Integration

The frontend communicates with a backend API using `axios`.
*   Ensure your backend server is running simultaneously (usually on port `5000`).
*   If you are experiencing connection issues (like `ECONNREFUSED` or 404 errors), verify that the backend is running correctly and that any proxy settings in your `vite.config.js` or environment variables in `.env` are correctly pointing to the backend's URL.
